# 《丹炉》游戏设计文档（GDD）

> 版本：v0.1（HTML 原型）
> 状态：原型验证阶段
> 目标平台：网页（原型）→ Godot 多平台（正式版）

---

## 1. 概述

### 1.1 一句话
一款"选素材 → 投炉 → 掐时机 → 炼成丹"的点击小游戏。

### 1.2 灵感来源
- 《塞尔达传说：旷野之息》烹饪系统 —— 素材自由组合、配方探索
- 抖音锻刀小游戏 —— 指针摆动的时机判定带来的紧张感与爽快感
- 中式修仙文化 —— 炼丹、药材、品阶

### 1.3 目标体验
- **易上手**：10 秒学会，点击三个时机即可开炼
- **有深度**：配方探索 + 品质追求 + 图鉴收集
- **爽快感**：判定成功时的丹成特效与品阶揭晓

### 1.4 平台与开发路径
| 阶段 | 平台 | 技术 | 目的 |
|---|---|---|---|
| v0.1 原型 | 网页 | 原生 HTML/CSS/JS | 验证玩法手感与循环 |
| v1.0 正式版 | PC / 移动 / Web | Godot 4.x | 完整美术、音效、多平台 |

## 2. 核心玩法循环

```
┌─────────────────────────────────────────────────────────┐
│  ① 选素材（背包中选 1~3 种）                              │
│        ↓                                                 │
│  ② 投炉（点击"开炼"）                                    │
│        ↓                                                 │
│  ③ 三段时机判定（锻刀式指针）                             │
│      [投炉时机] → [控火时机] → [出锅时机]                 │
│        ↓                                                 │
│  ④ 结算：按素材组合 + 判定得分出丹/失败                   │
│        ↓                                                 │
│  ⑤ 奖励：素材/金币，图鉴收录，解锁新素材                 │
└─────────────────────────────────────────────────────────┘
```

单局时长：约 30~60 秒。

## 3. 素材系统

### 3.1 素材类型
| 类型 | 定位 | 示例 |
|---|---|---|
| 草药 | 基础素材，决定丹药功能 | 灵芝、朱砂草、曼陀罗、雪莲 |
| 矿物 | 提升品阶上限 | 朱砂、寒晶、玄铁 |
| 兽材 | 稀有素材，解锁高级配方 | 兽骨、妖丹、龙鳞 |

### 3.2 素材属性
每个素材包含：

```jsonc
{
  "id": "lingzhi",
  "name": "灵芝",
  "type": "herb",            // herb | mineral | beast
  "emoji": "🍄",
  "tier": 1,                 // 素材品阶 1~5
  "natures": ["wen"],        // 药性：wen温 han寒 du毒 ping平 ling灵
  "value": 3,                // 灵气值（影响丹药品质上限）
  "desc": "百年灵芝，益气安神"
}
```

**药性相生规则（草案）**：
- 温 + 寒 = 中和（降低失败率，稳定出丹）
- 毒 + 灵 = 毒丹（特殊路线）
- 同类药性叠加 = 强化功能
- 相克药性（如 温+寒 之外冲突组合）= 爆炉风险

### 3.3 素材获取
- 初始赠送：灵芝×5、朱砂草×5、曼陀罗×3、兽骨×3、朱砂×3
- 炼药成功奖励：按丹药品阶返还 2~5 个关联素材
- 炼药失败：消耗素材，返还 1 个安慰素材
- 解锁：图鉴进度每解锁 3 个新丹药，解锁一种新素材（雪莲→寒晶→妖丹→龙鳞）
- 商店购买（见 §6.2）

### 3.4 素材选择
- 一次炼药可选 1~3 份素材，**允许同种素材放多份**（受持有数量限制），如灵芝×2 + 朱砂草可炼培元丹
- 素材卡显示已选数量，点击已选中卡片取消一份

## 4. 配方系统

### 4.1 配方结构
```jsonc
{
  "id": "huichun",
  "name": "回春丹",
  "grade": 1,                  // 丹药品阶需求（1~5）
  "materials": ["lingzhi", "zhushacao"],  // 素材组合（无序）
  "natures": ["wen"],          // 成品药性
  "effect": "恢复气血，疗伤圣药",
  "known": true                // 初始是否已知（图鉴显示）
}
```

### 4.2 判定规则
1. 投入的素材**组合与配方一致** → 按配方出丹
2. 组合不在配方表 → 按素材属性生成**随机丹药**（功能随机，品阶看素材）
3. 品阶 = 素材灵气均值 × 判定得分系数（见 §5.4）

### 4.3 丹药品阶
| 品阶 | 名称 | 判定要求 |
|---|---|---|
| 1 | 凡品 | 任一阶段成功即可 |
| 2 | 良品 | 至少 1 段"良好" |
| 3 | 珍品 | 至少 2 段"良好"或 1 段"完美" |
| 4 | 仙品 | 2 段"完美"以上 |
| 5 | 传说 | 3 段全"完美"（丹方组合专属） |

### 4.4 示例配方（v0.1 上线）
| 丹药 | 素材 | 药性 | 效果 | 品阶上限 |
|---|---|---|---|---|
| 回春丹 | 灵芝 + 朱砂草 | 温 | 恢复气血 | 3 |
| 聚气丹 | 朱砂草 + 朱砂 | 平 | 修炼加速 | 4 |
| 迷魂丹 | 曼陀罗 + 兽骨 | 毒 | 迷幻控制 | 3 |
| 培元丹 | 灵芝 + 灵芝 + 朱砂草 | 温 | 提升修为 | 4 |
| 寒息丹 | 雪莲 + 寒晶 | 寒 | 冰系抗性 | 4 |
| 破镜丹 | 雪莲 + 寒晶 + 妖丹 | 灵 | 突破瓶颈 | 5 |

## 5. 判定机制（锻刀式）

### 5.1 流程
投入素材后进入判定阶段，共 **3 段**，每段指针从左侧**匀速单向行进**至右侧（3 秒走完全程），玩家在指针经过右侧判定区时点击停止：

1. **投炉时机**（3s）—— 决定素材入炉状态
2. **控火时机**（3s）—— 决定火候
3. **出锅时机**（3s）—— 决定成丹

指针**走到底（到达最右端）仍未点击 → 该段自动判失败**。

### 5.2 区间划分（判定区集中在最右侧，指针位置 0~100）
| 区间 | 范围 | 得分 |
|---|---|---|
| 完美 | 84~96 | 3 分 |
| 良好 | 68~96（除完美） | 2 分 |
| 普通 | 48~96（除以上） | 1 分 |
| 失误 | <48（太早）或 >96（走过头） | 0 分 |

区间为嵌套结构：普通 ⊃ 良好 ⊃ 完美，全部贴右端。成功区整体宽度为初版两倍（普通 24→48 宽）。

### 5.3 随机性（老虎机要素）
- 指针行进带**低频正弦扰动**（周期约 3s、幅度 ±0.8，视觉丝滑，位置不完全确定，防纯背板）
- 5% 概率触发"丹炉灵气波动"：当前段区间整体偏移 ±5%（提示文案提示）
- 失误 ≥2 段 → 直接爆炉（炼药失败）

### 5.4 品质计算
```
素材灵气均值 avgValue = Σ(素材.value) / 素材数
判定得分 score = Σ(每段得分)          // 0~9
品质系数 factor = score / 9           // 0~1

丹药最终品阶 grade = clamp(floor(avgValue × factor + 0.5), 1, 5)
配方品质上限 = 配方.grade + 1         // 同配方可炼出更高品阶
```

## 6. 数值草案

### 6.1 素材表（v0.1）

| zhushacao | 朱砂草 | herb | 1 | 平 | 2 | 初始 |

### 6.2 经济与商店
**背包系统**：素材与成品丹药都入背包。丹药按 `丹药id@品阶` 分条目存储（如 `huichun@3` = 珍品回春丹 ×N），素材按 tier、丹药按品阶显示对应品级颜色（凡品灰/良品绿/珍品蓝/仙品紫/传说金）。

**商店（丹坊）**：买卖素材、买卖丹药、打听图鉴（解锁丹方信息）。

价格公式（economy.js，纯函数）：
| 项目 | 公式 |
|---|---|
| 素材买价 | `tier × 15 + value × 3`（灵芝 24，龙鳞 111） |
| 素材卖价 | 买价 ÷ 2 |
| 丹药卖价 | `实际品阶 × 20 + 基础品阶 × 10`（珍品回春丹 70） |
| 丹药买价 | 卖价 × 2（商店只售基础品阶） |
| 图鉴打听价 | `(配方品阶 + 1) × 50`（破镜丹 250） |

**经济循环**：卖丹/卖素材赚金币 → 买高级素材 → 炼更高品阶丹药 → 卖丹/打听图鉴 → 解锁新素材与丹方 → 更高价值循环。买图鉴不送丹药，丹药需自己炼（或高价购买），保证"炼药"始终是核心。素材与丹药买卖均按 1 个/次，按钮可连点。

### 6.3 单局节奏
- 素材选择：10s 内
- 三段判定：每段 2~5s（视点击时机）
- 结算：2s
- 目标：玩家 10 分钟内完成一次"配方探索→炼出珍品"的完整循环

## 8. 技术架构

### 8.1 原型（v0.1）
```
lingyao/
├── index.html        # 单页入口
├── style.css         # 样式
├── js/
│   ├── data.js       # 素材/配方数据（纯数据，无逻辑）
│   ├── judge.js      # 判定逻辑（纯函数）
│   ├── game.js       # 游戏状态机
│   └── ui.js         # DOM 渲染与交互
└── design/GDD.md     # 本文档
```

**模块职责**：
- `data.js`：MATERIALS / RECIPES 常量（JSON 结构）
- `judge.js`：`judgeScore(pos)` 区间判定、`calculateResult(materials, scores)` 品质计算 —— **纯函数，可单测**
- `game.js`：状态（背包/图鉴/金币）、流程控制
- `ui.js`：渲染 + 事件绑定，不包含游戏规则

### 8.2 Godot 移植规划（v1.0）
| 原型 | Godot 对应 |
|---|---|
| data.js 数据 | `res://data/materials.json` + `recipes.json`（1:1 转换） |
| judge.js 纯函数 | `res://scripts/judge.gd`（相同公式） |
| game.js 状态机 | `res://scripts/game_state.gd`（autoload 单例） |
| ui.js DOM 渲染 | 场景树 + Control 节点 |
| CSS 样式 | Theme / 样式表 |

**移植要点**：
- 判定公式、区间常量、配方数据保持与原型完全一致（数值验证过再动）
- UI 重做：Control 节点替代 DOM，动画用 Tween/AnimationPlayer
